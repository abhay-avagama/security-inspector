# Product

## Platform

web

## Users

Two audiences, served with equal weight:

- **Developers who run AI coding agents** (Claude Code, Cursor, Codex, Gemini) on their own laptop. They usually arrive from an alert (a Chrome or Playwright CVE, an MCP server flaw) and want a fast, trustworthy answer to "am I affected, and what do I do?".
- **People who run small Linux servers** (a VPS with WordPress, PostgreSQL, nginx, Apache, MariaDB). They want to know what to patch, judged against their own distro's fixed packages, not a version number that looks old.

Both are technical, short on time and wary of running scripts from the internet.

## Product Purpose

Am I affected? is one Python file that checks a laptop or Linux server for the vulnerabilities being exploited right now, plus the risky setup AI agents leave behind, and says what to do about each finding. With `--fix` it also applies the vendor's update for affected packages, one at a time and only after the user types yes. It is run with `curl -fsSL https://amiaffected.now/run | sh`, prints a table, can write an HTML report (`--html`), and exits with 1 when anything is affected so it can fail a CI job.

Success for Avagama Consulting, which builds and maintains it, is **reputation**: stars, shares, and being known as the people who track these issues carefully and quickly. Runs come first; enquiries for Avagama's agent security review are a quiet second step, never the page's headline.

## Positioning

A hand-picked list, not a general dependency scanner. It covers what generic scanners (osv-scanner, Trivy, Grype) don't: exploited bugs checked against each distro's own fixed builds, Chromium copies that Puppeteer and Playwright cache and never update, archived MCP servers, and how exposed a machine is to an AI agent (unpinned MCP servers, agent permissions, SSH keys without a passphrase, `.env` files in agent folders). New advisories are added within hours of disclosure, from a queue of CISA KEV and cve.now items checked every 6 hours.

## Operating Context

- People land from alerts, social posts (LinkedIn, X), Hacker News or GitHub, copy the one-liner, run it in a terminal, and read the table or the HTML report.
- On servers it runs as root over SSH; on laptops as the user.
- `--fix` asks at the terminal before every change, so it is run by a person, not from cron.
- Maintenance: a GitHub Action every 6 hours opens `queue` issues for new candidate CVEs; each is researched (vendor fixed versions, distro trackers), added to `advisories.json` with a test, and listed on the page and README.

## Capabilities and Constraints

- One file, `secinspect.py`, Python 3.8+ standard library only; data in `advisories.json`; installer `run` is a few lines of shell.
- macOS and Linux (Ubuntu, Debian, RHEL family). Windows trust stores only partially.
- `--fix` uses apt, dnf or Homebrew only, with commands built in `secinspect.py` from the package names the package manager reports; `advisories.json` decides which packages need an update and is never run. An update is offered only if the newest version in the machine's sources passes the same check. Kernels, self-updating apps and hand-installed software stay manual. Every step goes to a local hash-chained log (`/var/log/amiaffected/audit.jsonl` as root, `~/.local/state/amiaffected/audit.jsonl` otherwise), checked with `--verify-log`.
- Statuses: AFFECTED, REVIEW (configuration findings and unreleased fixes), UNKNOWN, OK, NOT FOUND. Agent-setup findings are always REVIEW and never change the exit code.
- Site is static HTML on GitHub Pages at amiaffected.now (Cloudflare DNS). The HTML report is generated by `html_report()` in `secinspect.py`, with inline CSS, light and dark.
- MIT licensed, source at github.com/abhay-avagama/security-inspector, with SECURITY.md and private vulnerability reporting enabled.

## Brand Commitments

Promises every version must keep:

- **Nothing leaves the machine.** No data about the machine is sent. The only network call is a read-only GET of the public cve.now feed to warn when advisory data is stale, and `--no-update-check` turns it off. With `--fix`, the package manager downloads updates from the sources the machine already uses; nothing goes to us.
- **Nothing changes without a yes.** `--fix` asks before every update, can't be told to skip asking, and refuses to run if its audit log has been edited.
- **One command, no install.** `curl | sh`, standard library only, no dependencies.
- **Readable before running.** The `run` script, `secinspect.py` and `advisories.json` are linked from the page so people can read them first.
- **No scare tactics.** Calm, plain wording: say what's affected and what to do. No alarm language, countdowns or fear-driven calls to action.

Voice: plain words, short factual sentences, Indian English spelling where it applies ("organisation"). Every claim points at a source (vendor advisory, NVD, CISA KEV). Findings show file paths, never secret values.

Credit line: "Built and maintained by Avagama Consulting" linking to avagama.co, with one low-key line pointing to the agent security review on avagama.co/services/.

## Product Principles

1. Earn trust before asking for anything: show exactly what the tool reads, runs and sends.
2. Accurate over alarming: a false "OK" is a security bug, and a false alarm wastes trust; distro backports and unreleased fixes are said plainly.
3. Every finding ends in an action: the command to run or the setting to change.
4. Stay narrow: exploited or critical issues in software people run on laptops and small servers, plus AI-agent exposure. Not a general scanner.
5. Fast to the answer: someone arriving from an alert should reach the one-liner and the relevant check in seconds.

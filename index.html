Am I affected?

One Python file that checks your machine for the Chrome bugs being exploited right now, the old browsers Puppeteer and Playwright leave behind, and the October 2026 PHP, Node.js, BIND, LiteLLM, GitLab and eMudhra issues, and tells you what to do about each one.

No dependencies, and nothing about your machine is sent anywhere. Python 3.8+ on macOS or Linux.

curl -fsSL https://amiaffected.now/run | sh

Rather read it first? run is ten lines; it fetches secinspect.py and advisories.json into a temp folder and runs them. Pass options after sh -s --:

curl -fsSL https://amiaffected.now/run | sh -s -- --html report.html   # HTML report
curl -fsSL https://amiaffected.now/run | sh -s -- --docker             # also scan Docker images
curl -fsSL https://amiaffected.now/run | sh -s -- ~/work               # only search this folder
curl -fsSL https://amiaffected.now/run | sh -s -- --skills-baseline ~/.amiaffected-skills.json   # also show what changed in your agent skills since last time
curl -fsSL https://amiaffected.now/run | sudo sh -s -- --install     # keep a copy that updates only from signed releases
sudo python3 /opt/amiaffected/secinspect.py --fix                     # then apply the updates you approve, one by one

--fix offers the update for each affected package through apt, dnf or Homebrew, from your distro or a vendor repository you added (nginx.org, PGDG, MySQL), and runs it only when you type yes. The commands are written in the script, never taken from the data file, and patches come only from the sources your machine already trusts. It checks again afterwards and keeps a local audit log that shows if any line was changed (--verify-log). How it works. --fix runs only from the installed copy, which checks every update against our offline release key (fingerprint SHA256:J2gtbuBTYxZRpDwEsKM6owYkY38bCClyuybzmeCu01U) and refuses anything unsigned. How signing works.

New checks land within a day of disclosure: see the changelog. Exit code is 1 if anything is affected, so it can fail a CI job. There's also a GitHub Action, and a watch mode for servers that posts to Slack or email only when something changes, including when a fix reaches your package sources.

If an AI agent works on this machine

On a Linux server

It reads /etc/os-release, lists every installed package with dpkg or rpm, and matches it against the distro vendor's own security notices, with anything on CISA's exploited list first. The notices are downloaded to the server and matched there; the package list isn't sent anywhere. Distro builds are judged by the vendor's fixed version, so a patched server isn't flagged just because the version number looks old. How it works.
